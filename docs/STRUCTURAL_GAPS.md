# Structural Gap Numeric Policy\n\nStructural-gap detection and deterministic positional evaluation operate on\nnumeric measurements that are currently represented as Python floats.\n\n## Comparison policy\n\nNumeric equality uses an explicit absolute tolerance of 1e-9.\n\nThis tolerance exists to prevent binary floating-point representation noise from\nbecoming a false epistemic difference. It is not an uncertainty model and does\nnot claim that measurements are accurate to 1e-9 units.\n\nThe policy distinguishes values that differ only by ordinary floating-point\nrepresentation noise from values whose difference is materially larger than\nthe declared comparison tolerance.\n\n## What this does not solve\n\nTolerance is not measurement uncertainty. A result reported as 7.0000001 with\nan instrument uncertainty of plus or minus 0.5 is not made trustworthy merely\nbecause its floating-point representation is handled correctly.\n\nFuture uncertainty-aware discovery must represent uncertainty explicitly and\ndefine the comparison rule for that uncertainty. Until then, the current numeric\npolicy prevents representation noise from masquerading as a discovery gap\nwithout pretending to adjudicate measurement error.\n\n## Boundary tests\n\nThe test suite requires both sides of the tolerance boundary:\n\n- 0.3 versus 0.1 + 0.2 must not produce a false accounting gap.\n- A residual materially larger than 1e-9 must still produce a gap.\n- A positional measurement within the tolerance of the expected position must\n  be treated as present by the deterministic evaluator.
